# pol-03 — Level A: the rules benchmarkit has about itself

Fill the first half of `mode_for` with the **built-in, non-configurable** rules,
and make them conditional on the workspace *being* the app. This is the task that
fixes the reported problem: point the working location at another project and its
`.env` becomes an ordinary file, visible in the tree and editable.

Depends on: pol-01 (the vocabulary), pol-02 (the matcher).

## 1. The condition, stated once

```python
# src/core/editorfs/builtin_policy.py
def is_self_workspace() -> bool:
    """True when the active workspace IS the benchmarkit install directory.

    One comparison, and `policy.workspace_root()` already does the resolving:
    `realpath(path_location()) == realpath(PROJECT_ROOT)`. Everything level A
    owns hangs on this, so it gets one function and one docstring rather than an
    inline `==` at each rule.
    """
```

Why it is a *condition* and not a global list: the rule that stops a pane editing
`.env` is not "`.env` is dangerous", it is "this app regenerates that file from
`SETTING_KEYS` on every settings save" (`config._render_env()`). The second
sentence is false for any other project, so the rule must be too. A workspace of
the app's own *parent*, or a copy of the repo, is not the app — the comparison is
exact, not a prefix.

## 2. The rules

```python
BUILTIN_RULES: tuple[tuple[str, str, str], ...] = (
    (".env**",      HIDDEN,    "regenerated from the settings template on every save"),
    ("logs/**",     HIDDEN,    "the app's own backups and trash"),
    ("web/dist/**", READ_ONLY, "vite build output"),
    ("resources/memory_registration.json", READ_ONLY,
     "fixed and self-healing, not a file to hand-edit"),
)
```

Matched with pol-02's `pattern_matches` against the **normalised workspace-
relative** path, returned as `Rule(mode, LEVEL_BUILTIN, pattern, reason, index)`
candidates for `mode_for`. Per rule:

* The `.env**` pattern covers `.env`, `.env.test` and any `.env.<something>` at
  any depth — the shape the current `DENY_FILE_PREFIXES = (".env",)` name check
  gives today (`path_policy.py:73`), as one readable pattern instead of a prefix
  list. It is `hidden`, not `ro`: today it is refused to *read* and to write
  alike, and the settings dialog is its only editor.
* The `logs/**` rule is new. `BACKUP_DIR` and `TRASH_DIR` live under `logs/`
  (`constants.py:64`, `:86`) and are deliberately outside the workspace *by path*
  — but when the workspace is the repo, they are inside the tree, so today the
  Editor can browse the app's own trash and its pre-save copies. That is a bug
  this lot should fix, and level A is where it belongs: a workspace pointed
  elsewhere has no reason to hide a folder called `logs`.
* **`web/dist/**`** is `ro`, not `hidden` — build output a user may want to look
  at, regenerated by `npm run build`.
* **No `.git` rule here.** By D6 that is a workspace-policy concern (present in
  every seeded file), not an app rule. Level A is only about files *this app
  writes*.

The reasons are not decoration: `refusal_message` (pol-01) echoes them, and
"benchmarkit hides this because the settings dialog regenerates it" is a
different conversation from "your policy hides it".

## 3. Reserve `.nojae` at the same time

`mode_for` answers `HIDDEN` for anything carrying a `POLICY_DIRNAME` component —
in **every** workspace, self or foreign, and whether or not the file loaded.
Implement it in `builtin_policy.py` as the one unconditional rule, on top of
`policy_modes.reserved_hit` (pol-01), and state in the docstring that no level-B
rule can override it (D5).

## 4. Wiring, and what must NOT change yet

Fill `list_builtin_rules(rel)` in `policy_modes.py`, so `mode_for` now answers
for level A. But **no surface calls `mode_for` until pol-06**: the tree, the read
route and the write routes keep behaving as today through
`listable`/`writable`/`refusal`. Deliberate — pol-03 must not both introduce
level A and remove the deny-list, or the intermediate state has a window where
`.env` is unprotected.

Add the reverse assertion instead: a test that the two answers **agree for this
workspace** on the paths that matter (`.env`, `.env.test`, `.git/config`,
`logs/trash/x`, `src/config.py`), which is what makes pol-06's swap a proven
non-event on the app's own repo *before* it happens.

## 5. Tests

New `tests/test_editorfs_builtin_policy.py` (pure `mode_for` calls plus one
route-level test):

1. workspace patched to the **app root**: `.env` → hidden/`LEVEL_BUILTIN`,
   `.env.test` → hidden, `sub/.env.local` → hidden; `notes.env` → **not** matched
   by this level (not app-owned, and D6 leaves it a workspace concern);
2. workspace patched to a **foreign `tmp_path`**: `.env` → `rw`, `logs/x` → `rw`,
   `web/dist/app.js` → `rw`. Pin this hard — it is the point of the task, and the
   test that fails if anyone moves level A back to being unconditional;
3. `is_self_workspace()` is False for the app's parent and for a sibling copy,
   not only for a far-away dir (the comparison is exact);
4. `.nojae`, `.nojae/read-write-policy.json`, `a/.nojae/b` → hidden in **both**
   workspaces, level = builtin;
5. the §4 agreement test against `editorfs.listable`/`writable`, on the app's own
   repo;
6. `mode_for("src/config.py")` is `rw` in both workspaces — level A is narrow.

Patch the workspace root through the mechanism the suites already use: set
`BENCHMARKIT_PATH_LOCATION` (see the `workspace` fixture in
`tests/test_editorfs.py`). Never monkeypatch `path_location` itself — that stubs
away the *comparison* this task is about.

## Notes for whoever executes it

* Keep the rules a **tuple of tuples**, not a dict: order is part of the
  semantics (pol-01's tie-break reads the index).
* Each reason string belongs next to its rule in code, for the same reason
  `constants.BACKUP_DIR` carries its rationale in a comment.
* If a rule ever needs to apply to a foreign workspace, it is the wrong rule for
  this file — it belongs in the seeded policy (pol-05).

## Deviation applied when executing it

The `.env**` pattern in §2 does not do what its own bullet says, and shipped as
`**/.env**`:

* pol-02's `**` absorbs components **in front of** what follows it, and the
  subtree rule only ever adds components **after** the whole pattern is consumed
  (see pol-02's notes). So `.env**` matches `.env`, `.env.test` and `.envx/y` —
  all at the workspace root — and **not** `sub/.env.local`, which §2 claims it
  covers.
* §2's stated goal is to reproduce the shape of the current floor, and that floor
  is `name.startswith(".env")` on the **last component** (`path_policy.py:131`),
  which does reach `sub/.env.local`. Only `**/.env**` does both.

Carry-over for pol-04/05/06: because the `**` sits on the *name*, the rule keeps
the prefix semantics, so `.envrc` and `.environment` are hidden too. That is
today's behaviour, not a new one, and the test pins it rather than hiding it. If
pol-05's seeded file ever wants the name-only shape, it is `.env` plus `.env.*`.

Three smaller things worth knowing before pol-06:

* **The reserved-folder test is one shared function, not a copy.** Level A needs
  the same answer `policy_modes.reserved_hit` gives, so the component loop moved
  into `mcp_connectors/policy_glob.reserved_component_hit(rel, dirname)` and
  `reserved_hit` now delegates to it. It belongs in that module because pol-08's
  two stdio connectors must reach it and cannot import `src` — the same argument
  the matcher and the parser have. The name is still read through
  `constants.POLICY_DIRNAME`, so `test_the_reserved_name_is_patchable_through_constants`
  keeps passing.
* **`is_self_workspace` compares `constants.PROJECT_ROOT`**, not a second
  `from src.config import PROJECT_ROOT`: same directory, and it makes both sides
  of the comparison call-time lookups, so a test can build the app's *parent* and
  a *sibling copy* as real paths instead of mocking one side.
* **§4's agreement test is agreement plus listed deltas.** The two answers cannot
  agree on this repo — level A newly hides `logs/**` (the fix in §2) and newly
  makes `web/dist` `ro`, while the live floor still refuses `.git`, `.ssh`,
  `id_rsa` and `mcp_connectors`, which level A deliberately does not own (D6,
  §5). So the test asserts equality on the overlapping paths and pins each
  difference by name, tightening or floor-only, which is the list pol-06 has to
  end up with instead of discover.
